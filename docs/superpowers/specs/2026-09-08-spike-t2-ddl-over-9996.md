# Спайк T2: DDL через канал 9996

**Дата:** 2026-09-08
**Статус:** закрыт, риск №1 снят
**Стенд:** Denodo Platform 9.5.1 в контейнере, `denodo-sqlalchemy` 2.0.5, SQLAlchemy 2.0.41,
`psycopg2-binary`; пользователь с правами администратора
**Скрипт:** `spikes/t2_ddl_over_9996.py` — `uv run spikes/t2_ddl_over_9996.py --env dev`,
профиль из `~/.denodo/profiles.toml`, всё создаётся в базе `denodo_skills_test` и
удаляется в конце. Финальный прогон: 89 шагов, 0 расхождений с ожиданием.

---

## 1. Ответ на вопрос спайка

**DDL через `denodo+psycopg2` на порту 9996 проходит целиком.** Через один канал
прошла вся VQL-цепочка v1: `DATABASE → FOLDER → TAG → DATASOURCE DF → WRAPPER DF →
TABLE → VIEW → INTERFACE VIEW → ASSOCIATION`, назначение тега, `SELECT` из каждого
уровня, `DESC VQL` и `DROP ... IF EXISTS`. Ни одна операция из перечня объектов v1 не
нуждается в REST-транспорте. Раздел 7.3 спеки остаётся в силе: `api_rest` нужен только
Data Marketplace (T11).

DDL проходит и внутри неявной транзакции psycopg2 (объект виден из другого соединения
после `commit()`), и в автокоммите. Рабочий режим для `scripts/denodo` — автокоммит,
см. 3.1.

## 2. Идемпотентность (раздел 6.4 спеки) — подтверждено на живом сервере

| Проверка | Результат |
|---|---|
| `CREATE OR REPLACE` для всех девяти проверенных типов (`DATABASE`, `FOLDER`, `TAG`, `DATASOURCE DF`, `WRAPPER DF`, `TABLE`, `VIEW`, `INTERFACE VIEW`, `ASSOCIATION`) | второй проход поверх существующих объектов — без ошибок, цепочка после него отвечает на `SELECT` |
| `CREATE` без `OR REPLACE` поверх существующего | ошибка; тексты в разделе 5 |
| `DROP ... IF EXISTS` для тех же типов | работает для **всех**, не только для тега; повторный `DROP ... IF EXISTS` по уже удалённому объекту — без ошибки |
| `DROP` без `IF EXISTS` по несуществующему | ошибка `The database does not contain the specified view` |
| `CREATE OR REPLACE TAG` без `ADD_TO` поверх тега с назначениями | назначения **сохраняются** |
| `CREATE OR REPLACE DATABASE` | обновляет описание, содержимое базы не трогает |

Не проверялись `DATASOURCE JDBC`, `WRAPPER JDBC`, `DATASOURCE JSON`, `WRAPPER JSON` —
у них тот же синтаксис `CREATE OR REPLACE` и `DROP ... IF EXISTS`, подтверждение придёт
из T12 вместе с пометками `verified:`.

## 3. Что нужно знать слою исполнения (T5)

### 3.1 Автокоммит включается на DBAPI-соединении, не через SQLAlchemy

`create_engine(url, isolation_level="AUTOCOMMIT")` падает с `NotImplementedError`:
диалект Denodo урезан от PostgreSQL и не реализует `set_isolation_level`. Рабочий
способ — событие `connect`:

```python
@sa.event.listens_for(engine, "connect")
def _autocommit(dbapi_conn, _record):
    dbapi_conn.autocommit = True
```

### 3.2 `%` в VQL ломается о psycopg2

`conn.exec_driver_sql(vql)` передаёт в psycopg2 пустой словарь параметров, и psycopg2
пытается интерполировать каждый `%` — `LIKE 'New%'` падает с
`immutabledict is not a sequence`. Два рабочих варианта:

- сырой курсор без параметров: `conn.connection.cursor().execute(vql)` — psycopg2
  не трогает строку, `%` проходит как есть;
- экранирование `%%` перед `exec_driver_sql`.

Для транспорта предпочтителен сырой курсор: VQL пользователя не должен переписываться.

### 3.3 `sqlalchemy.text()` и двоеточие в декларациях типов

`cust_id:text` через `text()` проходит: двоеточие после буквы SQLAlchemy не считает
bind-параметром. Но `( :text` — с пробелом перед двоеточием — уже считает, и запрос
падает с `A value is required for bind parameter`. Через `text()` VQL не гонять.

### 3.4 `CONNECT DATABASE` переключает сессию

Работает через 9996 и действительно меняет текущую базу соединения: папка, созданная
после `CONNECT DATABASE denodo_skills_test`, оказалась в тестовой базе. Два следствия:

- многофайловые VQL-скрипты стенда с `CONNECT DATABASE` внутри исполнимы как есть;
- **`DROP DATABASE` из соединения, которое к этой базе подключено (в URL или через
  `CONNECT`), запрещён**: `This database cannot be dropped because the connection was
  established with this database`. Пул SQLAlchemy переиспользует такое соединение, и
  ошибка всплывает в неожиданном месте — перед `DROP DATABASE` нужно `engine.dispose()`
  или отдельный движок к `admin`.

### 3.5 Несколько выражений через `;` в одном `execute` проходят

Файл `.vql` можно отправлять одним вызовом — сервер разбирает `;` сам. Что при этом
происходит с ошибкой в середине файла (откат? продолжение?), не проверялось — это
вопрос T5.

### 3.6 Машиночитаемая обратная связь

- `DESC VIEW <v>` — строки `(имя, тип, код типа, …)` — годится для проверки схемы.
- `DESC VQL VIEW <v>` — одна строка с полным VQL представления и всех его зависимостей,
  сгенерированным сервером (это ещё и эталон синтаксиса: сервер печатает
  `DROP ... IF EXISTS ... CASCADE` перед каждым `CREATE`).
- `DESC VQL DATABASE <db>` — первая строка `# Generated with Denodo Platform 9.5.1.`
  даёт версию сервера. `GETVERSION()` как функция или процедура на 9.5.1 не найдена.
- `LIST DATABASES`, `GET_ELEMENTS()` с фильтром по `input_database_name`,
  `GET_VIEW_TAGS()` — работают. `GET_ELEMENTS()` по несуществующей базе — ошибка, а не
  пустой результат.

## 4. Что нужно знать доменным навыкам (T6, T8a–T8c)

### 4.1 Теги VDP: `ADD_TO` и `REMOVE_FROM` обязательны вместе

Форма из документации и из объёма v1 — `ADD_TO (VIEWS (...) COLUMNS (...))` — сама по
себе синтаксическая ошибка. На 9.5.1 парсер требует **оба блока**, каждый с обеими
секциями, даже пустыми:

```sql
ALTER TAG spike_tag
    ADD_TO      ( VIEWS ( denodo_skills_test.spike_dv ) COLUMNS ( denodo_skills_test.spike_bv.country ) )
    REMOVE_FROM ( VIEWS () COLUMNS () );
```

Представления и колонки — только с именем базы. Убрать `REMOVE_FROM` или `COLUMNS ()`
— ошибка `Exception parsing query near ''`. То же для `CREATE OR REPLACE TAG ... ADD_TO`.
`ALTER TAG <name> DESCRIPTION = '...'` работает. Формы `ALTER VIEW ... TAGS (...)` и
`ALTER VIEW ... ADD TAGS (...)` не существуют. Второй рабочий путь — `TAGS (<tag>)`
прямо в `CREATE OR REPLACE VIEW`.

### 4.2 Wrapper DF обязан перечислять все колонки CSV

Wrapper с тремя колонками из восьми создаётся без ошибки, базовое представление над
ним тоже, а `SELECT` возвращает **ноль строк без единого предупреждения**. Wrapper со
всеми восемью колонками отдаёт данные. Для навыка `datasources` это правило шаблона:
`OUTPUTSCHEMA` — полный заголовок файла, а сужение колонок делается в базовом
представлении или производном.

Это также единственный случай в спайке, где объект «создался успешно», но не работает,
— аргумент в пользу `SELECT` как обязательной части верификации (раздел 11.1).

### 4.3 Синтаксис, на котором спайк споткнулся

| Объект | Ошибка | Как правильно |
|---|---|---|
| `CREATE TABLE` (базовое представление) | `CACHE OFF` сразу перед `ADD SEARCHMETHOD` — `Exception parsing query near 'ADD'` | `CACHE OFF TIMETOLIVEINCACHE DEFAULT ADD SEARCHMETHOD ...` |
| `CREATE INTERFACE VIEW` | `SET IMPLEMENTATION` после `FOLDER` — ошибка near `SET` | `( поля ) SET IMPLEMENTATION <view> FOLDER = '...'` |
| `CREATE INTERFACE VIEW` | тип `bigint` — `error while loading the type of the field 'bigint'` | VQL-типы: `long`, `text`, `timestamp`, … |
| `CREATE TAG` | описание литералом без ключевого слова — ошибка near `'` | `DESCRIPTION = '...'` |
| `DROP FOLDER` | папка с подпапками — `folder ... contains elements and can not be dropped` | удалять снизу вверх; `IF EXISTS` не помогает |

`ALTER INTERFACE VIEW <iv> SET IMPLEMENTATION <view>` работает — можно создавать
интерфейс заранее и подставлять реализацию позже.

## 5. Тексты ошибок для `references/errors.md` (T7)

Все прилетают как `psycopg2.OperationalError`, текст сервера повторён в `DETAIL:
java.sql.SQLException: ...`. Кодов нет — только текст.

| Ситуация | Текст |
|---|---|
| `CREATE DATABASE` поверх существующей | `error creating database: Database already exists` |
| `CREATE FOLDER` поверх существующей | `Error creating folder: /spike already exists` |
| `CREATE TAG` поверх существующего | `Invalid tag name: already exists` |
| `CREATE DATASOURCE` поверх существующего | `error creating new data source: Duplicate object identifier` |
| `CREATE WRAPPER` поверх существующего | `Error creating new Wrapper: Duplicate object identifier` |
| `CREATE TABLE` / `CREATE VIEW` поверх существующего | `invalid view name: already exists` |
| `CREATE VIEW` над несуществующим | `View 'spike_bv' not found` |
| `CREATE ASSOCIATION` над несуществующим | `Error loading referenced views` |
| `DROP` несуществующего представления | `error removing view: The database does not contain the specified view: spike_bv` |
| `DROP DATABASE` из подключённого к ней соединения | `This database cannot be dropped because the connection was established with this database` |
| `DROP FOLDER` с содержимым | `error dropping folder: folder /spike contains elements and can not be dropped` |
| синтаксис | `Syntax error: Exception parsing query near '<токен>'` |
| неизвестная функция | `Function 'getversion' with arity 0 not found` |
