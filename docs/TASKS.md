## Сейчас

### T1. Определить перечень функций v1

**Статус:** сейчас
**Блокирует:** T6, T7, T8

Выбрать **5–10 классов объектов Denodo**, которые войдут в первую версию. Не больше.

Отправная точка из спеки (раздел 12): базовая инфраструктура, нужная почти в любом
проекте, — виртуальные базы, папки, теги; источники, wrappers, base views; производные
представления.

Что нужно на выходе:

- список из 5–10 объектов с точными названиями VQL-команд;
- для каждого — к какому навыку он относится (`catalog` / `datasources` / `views`);
- для каждого — нужен ли живой внешний источник для верификации, или достаточно
  проверки синтаксиса (см. раздел 11.1 спеки);
- явно названные объекты, которые рассматривались и **не** вошли, с причиной.

Критерий отбора: объект попадает в v1, если без него нельзя довести до конца сценарий
«описал текстом → на платформе появилась работающая витрина».

## Дальше

### T2. Спайк: проходит ли DDL через канал 9996

**Статус:** дальше
**Блокирует:** T5

Риск №1 из спеки (раздел 13). Подключиться `denodo-sqlalchemy` к живому стенду и
выполнить по очереди `SELECT 1`, `CREATE VIEW`, `CREATE DATASOURCE`.

Ответ определяет, насколько нагружен REST-транспорт в v1. Если DDL не проходит — часть
операций уходит в `api_rest`, и это меняет объём задачи T5.

Побочно проверить: какие конструкции идемпотентности (`CREATE OR REPLACE`,
`IF NOT EXISTS`) Denodo 9.5 поддерживает и для каких типов объектов (раздел 6.4).
